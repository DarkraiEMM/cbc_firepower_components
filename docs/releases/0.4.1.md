# CBC: Firepower Components 0.4.1

## 中文

### 适用版本

- Minecraft 1.21.1 / NeoForge 21.1.x
- Create 6.0.x
- Create Big Cannons 5.11.7
- Create: Radar 4.9 继续使用旧版兼容路径；Create: Radar 5.0 EA 使用新的正式炮座 API 路径。
- Forge 1.20.1 是独立维护线，本次不升级。

### Create: Radar 5.0 EA 兼容

- 为紧凑型火炮炮座、紧凑型自动炮炮座和竖直紧凑型炮座接入 Radar 正式炮座 API。
- 补全 Radar 5.0 中公开炮座适配器未覆盖的 CBC 火控上下文，使数据链可以建立完整的跟踪、弹道解算和开火流程。
- 将 Radar 开火控制器的真实输出传递给已关联的紧凑炮座。
- 在目标丢失、数据链改变、炮座关联变更或区块卸载时显式停火，避免炮座继续向最后位置射击。
- Radar 4.9 的旧版 Mixin 与 Radar 5.0 API 适配互斥加载，避免两套控制逻辑同时生效。

### 炮座与自动控制

- 自动火炮控制器现在可以向 CBC 原版固定式炮座提供虚拟开火信号。
- 固定式炮座仍保留原有物理红石输入；物理信号与自动控制信号可以独立使炮座开火。
- 连续射击改为失效安全的电平控制；控制信号或炮座关联消失后会停止自动开火。

### 崩溃与模型修复

- 修复竖直紧凑型炮座朝下时，玩家退出手动操控会因对 `DOWN` 方向调用水平旋转而导致的服务端崩溃。
- 下车位置搜索现在会将垂直炮管方向转换为炮座的水平参考方向，再检查周围空间与地面。
- 补全单管大型自动炮炮尾缺失的推拉栓状态模型。
- 统一单管大型自动炮炮尾的纹理槽引用，修复错误材质与 UV 堆叠显示。

### 验证

- 已对 Create: Radar `5.0-EA-1.2.2-1.21.1` 实际 JAR 的公开 API、CBC 炮座上下文、武器网络查询和开火控制器字节码签名进行了核对。
- NeoForge 1.21.1 发布构建已通过。
- 已在完整游戏组合中确认紧凑炮座可以接受 Radar 5.0 EA 的水平、俯仰、跟踪和自动开火控制。

### 已知的上游限制

- Create: Radar 5.0 EA 的 `ApiMountPitch.atTargetPitch(...)` 当前没有采用武器适配器提供的最小开火容差，而是固定使用 `0.1°`。因此 Sable 物理结构上的移动目标可能继续保持锁定，但 Radar 会停止输出开火信号。本版本不覆写 Radar 的内部判定，等待其上游修复。

## English

### Supported versions

- Minecraft 1.21.1 / NeoForge 21.1.x
- Create 6.0.x
- Create Big Cannons 5.11.7
- Create: Radar 4.9 continues to use the legacy compatibility path; Create: Radar 5.0 EA uses the new official mount-API path.
- The Forge 1.20.1 line is maintained separately and is not updated by this release.

### Create: Radar 5.0 EA compatibility

- Registered the Compact Cannon Mount, Compact Autocannon Mount, and Vertical Compact Cannon Mount through Radar's official mount API.
- Added the CBC weapon context still required by Radar 5.0 beyond its public mount adapter, allowing the data-link network to establish its complete tracking, ballistic-solution, and firing flow.
- Forwarded the real output of Radar's fire controller to the associated compact mount.
- Explicitly stops firing after target loss, data-link changes, mount reassignment, or fire-controller chunk unload, preventing a mount from continuing to fire at its last commanded point.
- Kept the Radar 4.9 legacy Mixins mutually exclusive with the Radar 5.0 API integration.

### Mount and automatic-control fixes

- The Automatic Cannon Controller can now provide a virtual firing signal to CBC's fixed cannon mount.
- Fixed mounts retain their normal physical redstone input; either physical redstone or the automatic controller may independently keep the mount firing.
- Continuous fire now uses fail-closed level control and stops when its control signal or mount association disappears.

### Crash and model fixes

- Fixed a server crash when a player dismounted from a downward-facing Vertical Compact Cannon Mount. The old path attempted a horizontal rotation of the vertical `DOWN` direction.
- Dismount placement now converts a vertical cannon direction to the mount's horizontal reference before checking nearby clearance and floor support.
- Restored missing sliding-block state models for the single-barrel large-autocannon breech.
- Normalized the breech texture-slot references to fix incorrect materials and stacked UV rendering.

### Validation

- Compared the integration against the actual Create: Radar `5.0-EA-1.2.2-1.21.1` JAR, including its public API, CBC mount context, weapon-network lookup, and fire-controller bytecode signatures.
- The NeoForge 1.21.1 release build completed successfully.
- Confirmed in the complete mod stack that compact mounts accept Radar 5.0 EA yaw, pitch, tracking, and automatic-fire control.

### Known upstream limitation

- Create: Radar 5.0 EA currently ignores the weapon adapter's minimum firing tolerance in `ApiMountPitch.atTargetPitch(...)` and always uses `0.1°`. A target moving on a Sable physics structure can therefore remain locked while Radar withholds its fire signal. This release does not override Radar's internal firing decision and awaits an upstream fix.
